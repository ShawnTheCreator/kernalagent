## Data Flow: How a User Request Becomes Action

### Simple Example: "Create a file with my name"

```
1. User Voice Input or Text Command
   │
   └─→ "Create a file with my name"
        │
        ▼
2. Desktop App receives command
   │
   └─→ VoiceToActionService.cs processes intent
        │
        ▼
3. Send to Backend API
   │
   └─→ POST /api/dashboard/intent
   │   Authorization: Bearer {JWT_TOKEN}
   │   Body: { "goal": "Create a file with my name" }
        │
        ▼
4. Backend routes to Microservice
   │
   └─→ Forward request (or cached result)
        │
        ▼
5. Microservice (Python) Processes
   │
   ├─→ Gemini 2.5 Flash analyzes request
   │   Generates action plan:
   │   [
   │     {"action": "create_file", 
   │      "path": "C:/Users/UserName/Documents/file.txt",
   │      "content": "Created by Kernel Agent"}
   │   ]
   │
   └─→ Executor Engine validates & sequences
        │
        ▼
6. Return Action Plan to Desktop App
   │
   └─→ JSON over HTTP:
       {
         "actions": [
           {
             "action": "create_file",
             "path": "C:/Users/UserName/Documents/file.txt",
             "content": "Created by Kernel Agent"
           }
         ]
       }
        │
        ▼
7. Desktop App Executes Plan
   │
   ├─→ SmartExecutor.ExecuteSingleAction("create_file", step)
   │   └─→ File.WriteAllText(path, content)
   │       ✓ File created successfully
   │
   └─→ Log result:
       {
         "action": "create_file",
         "success": true,
         "path": "C:/Users/UserName/Documents/file.txt"
       }
        │
        ▼
8. Report Success to User
   │
   └─→ "✓ File created at C:/Users/UserName/Documents/file.txt"
```

## Enhanced Data Flow: Complex Task with Autonomous Planning (Phase 3)

### Complex Example: "Organize my downloads folder by file type"

```
1. User High-Level Goal
   │
   └─→ "Organize my downloads folder by file type"
        │
        ▼
2. Desktop App sends to Microservice
   │
   ├─→ URL: POST /api/task/plan
   │   Body: {
   │     "goal": "Organize my downloads folder by file type",
   │     "context": {
   │       "active_window": "File Explorer",
   │       "open_apps": ["Explorer"],
   │       "downloads_path": "C:/Users/UserName/Downloads"
   │     }
   │   }
   │
   └─→ Timeout: 10 seconds
        │
        ▼
3. Task Planner (Python) Analyzes Goal
   │
   ├─→ Gemini 2.5 Flash processes:
   │   "You are task automation expert. Break down this goal
   │    into detailed executable steps for Windows PC"
   │
   └─→ Gemini responds with step-by-step plan:
       [
         {
           "step_number": 1,
           "description": "Open File Explorer to access downloads",
           "action": "open_app",
           "target": "explorer.exe"
         },
         {
           "step_number": 2,
           "description": "Navigate to Downloads folder",
           "action": "navigate",
           "target": "shell:Downloads"
         },
         {
           "step_number": 3,
           "description": "Create Documents folder for PDFs",
           "action": "create_file",
           "path": "Documents",
           "content": ""
         },
         ... (more steps)
       ]
        │
        ▼
4. Return Detailed Plan to Desktop App
   │
   └─→ TaskPlan object with:
       - total_steps: 8
       - estimated_duration: 15000ms
       - steps: [array of actions]
        │
        ▼
5. Desktop App Presents Plan to User
   │
   ├─→ [Preview]
   │   1. Open File Explorer
   │   2. Navigate to Downloads
   │   3. Create Documents folder
   │   4. Create Images folder
   │   5. Move *.pdf to Documents
   │   6. Move *.jpg,*.png to Images
   │   7. Move *.docx,*.xlsx to Documents
   │   8. Create summary report
   │
   └─→ [User clicks] "Execute" or "Edit Plan"
        │
        ▼
6. Desktop App Executes Plan
   │
   ├─→ For each step in plan:
   │   ├─→ Execute action via SmartExecutor
   │   ├─→ Capture result (success/failure)
   │   ├─→ If failed: Send to Recovery Agent
   │   │   Recovery Agent:
   │   │   - Analyzes failure
   │   │   - Asks Gemini: "How to recover from this?"
   │   │   - Executes recovery action
   │   │   - Continues with next step
   │   └─→ Continue with next step
   │
   └─→ Track overall progress:
       ✓ Step 1 complete
       ✓ Step 2 complete
       ✓ Step 3 complete
       ✓ Step 4 complete
       ✓ Step 5 complete (moved 12 PDFs)
       ✓ Step 6 complete (moved 8 images)
       ✓ Step 7 complete (moved 5 documents)
       ✓ Step 8 complete
        │
        ▼
7. Report Success & Summary
   │
   └─→ "✓ Task completed successfully!
         - Organized 47 files
         - Created 4 folders
         - Duration: 42 seconds
         - Success rate: 100%"
```

## Component Interaction: How Features Work Together

### Scenario: "Click the blue button that says Download"

```
Desktop App (WinUI 3)
    │
    ├─→ SmartExecutor: "click_element" with target "Download button"
    │
    ├─→ [Try Method 1] UIElementFinder
    │   └─→ Search accessibility tree
    │       └─→ Found! (85% confidence)
    │           └─→ ✓ Click immediately (10ms - FAST!)
    │
    └─→ [Skip Method 2] Vision (not needed - found via accessibility)
```

### Alternative Scenario: "Click that blue button over there"

```
Desktop App (WinUI 3)
    │
    ├─→ SmartExecutor: "find_and_click" with description "blue button"
    │
    ├─→ [Try Method 1] UIElementFinder
    │   └─→ Search accessibility tree
    │       └─→ Not found (ambiguous - could be any button)
    │
    └─→ [Try Method 2] Vision (Gemini Analysis)
        │
        ├─→ Take screenshot
        ├─→ Send to Microservice
        ├─→ Gemini Vision analyzes: "I see a blue button at coordinates (342, 156)"
        └─→ EnhancedVisionEngine returns:
            {
              "success": true,
              "x": 342,
              "y": 156,
              "confidence": 0.92,
              "element": "blue download button"
            }
            │
            └─→ ✓ Click at (342, 156) (500ms - SLOWER but ACCURATE!)
```

## Security & Sandboxing

```
┌─────────────────────────────────────────────────┐
│         Security Policy Service 🔒              │
│  Prevents unauthorized access                   │
└─────────────────────────────────────────────────┘
           │
           ├─→ Whitelist Check
           │   File operations only allowed in:
           │   ├─ C:\Users\[USERNAME]\Downloads
           │   ├─ C:\Users\[USERNAME]\Documents
           │   └─ C:\Users\[USERNAME]\Desktop
           │
           ├─→ Process Kill Restriction
           │   Cannot kill:
           │   ├─ explorer.exe (Windows Explorer)
           │   ├─ svchost.exe (System Services)
           │   └─ Other critical system processes
           │
           └─→ App Launch Restriction
               Can't open:
               ├─ Registry Editor
               ├─ Task Manager (user action only)
               └─ Other dangerous tools

All operations are logged for audit trail.
```

## Performance Metrics

### Action Execution Times

```
Action Type                  Time      Notes
─────────────────────────────────────────────────
click (coordinate)           15-30ms   Native mouse event
type_text (simple)           5-10ms    Per character + delays
open_app (system)            500-2000ms File I/O + process spawn
list_files (small dir)       20-50ms   Directory scan
find_files (recursive)       100-500ms Depends on folder size
find_element (UI)            10-50ms   Accessibility tree search
vision_targeting            500-1500ms Microservice + Gemini
wait_for_window              100-10000ms Polling + timeout
process_lookup               10-30ms   Windows API call
file_copy (large)            1000+ms   Depends on file size

Batch Execution (ActionChain):
Sequential:  Sum of all individual times
Parallel:    Time of longest action
```
